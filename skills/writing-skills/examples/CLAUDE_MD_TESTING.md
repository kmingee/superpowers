测试不同的文档版本，找出究竟怎样的写法能让智能体在压力下真正发现并使用技能。


## 要测试的文档版本

### NULL（基线——没有技能文档）
CLAUDE.md 中完全不提技能。

### 版本 A：温和建议
```markdown
## Skills Library

你可以访问 `~/.claude/skills/` 中的技能。开始任务之前，
可以考虑检查是否有相关技能。
```

### 版本 B：明确指令
```markdown
## Skills Library

开始任何任务之前，检查 `~/.claude/skills/` 中是否有
相关技能。存在技能时，你应该使用它。

Browse: `ls ~/.claude/skills/`
Search: `grep -r "keyword" ~/.claude/skills/`
```

### 版本 C：Claude.AI 强调式风格

## 测试协议

对每个版本：

1. **先运行 NULL 基线**（没有技能文档）
   - 记录智能体选择哪个选项
   - 捕获精确合理化借口

2. **在同一场景运行该版本**
   - 智能体会检查技能吗？
   - 找到技能后会使用吗？
   - 如果违规，记录合理化借口

3. **压力测试**——增加时间/沉没成本/权威压力
   - 压力下仍会检查吗？
   - 记录遵从在哪些条件下崩溃

4. **元测试**——询问智能体如何改进文档
   - “你有这份文档，但没有检查。为什么？”
   - “文档怎样写会更清楚？”

## 成功标准

**版本成功，如果：**
- 智能体在无人提醒时主动检查技能
- 智能体行动之前完整阅读技能
- 智能体在压力下仍遵循技能指导
- 智能体无法合理化绕过要求

**版本失败，如果：**
- 即使没有压力也跳过检查
- 不阅读技能，只“采用这个概念”
- 在压力下用理由绕过
- 把技能当作参考而不是要求

## 预期结果

**NULL：** 智能体选择最快路径，没有技能意识

**版本 A：** 没有压力时可能会检查，压力下容易跳过

**版本 B：** 有时会检查，但很容易合理化跳过

**版本 C：** 遵从度高，但可能感觉过于严格

**版本 D：** 更平衡，但更长——智能体会内化它吗？
